# ארכיטקטורת CureBot — סוכן שירות ומכירות לקליניקה

מסמך זה נועד לשני דברים: להבין איך הסוכן בנוי, ולשכפל אותו לקליניקה או עסק אחר.

## 1. מה הסוכן עושה

מקבל כל פנייה בוואטסאפ, מבין מה הפונה צריך, עונה בעברית חמה בסגנון שיחה, ומוביל לשיחת היכרות ביומן. מזהה מצוקה ובקשה לאדם, משהה את עצמו ומתריע לבעלת הקליניקה. הוא נשמע אנושי, אבל לא טוען שהוא בן אדם.

## 2. מסלול של הודעה אחת

```
פונה בוואטסאפ
  → Meta WhatsApp Cloud API
  → POST /api/meta/webhook      (אימות חתימה, מחזיר 200 מיד)
  → עיבוד ברקע (waitUntil)
  → handleIncoming()            הליבה, לא תלויה בערוץ
       כפילות?  מושהה?  → מדלגת
       היסטוריה מ-Redis (20 הודעות אחרונות)
       Claude (lib/anthropic.ts)  = פרומפט + ספריית תוכן
       הסרת סמנים [[END]] [[HUMAN]] [[ALERT]]
       שמירת שיחה + סימון (ליד חם / אדם / מצוקה / הסתיים)
  → sendText() חזרה לפונה
  → אם מצוקה או אדם: notifyOwner() (מייל, ובהמשך תבנית וואטסאפ)
```

## 3. הרכיבים

| קובץ | תפקיד | משתנה בין קליניקות? |
|---|---|---|
| `lib/prompt.ts` | אופי, גבולות, בטיחות, הסמנים | כן, זה הלב |
| `lib/knowledge.ts` | ידע על השיטה, שאלות נפוצות, התנגדויות, מה אסור | כן |
| `lib/core.ts` | ההחלטות: כפילות, השהיה, כרטיס סיום, גיבוי | לא |
| `lib/anthropic.ts` | קריאה ל-Claude, 3 ניסיונות, cache לפרומפט | לא |
| `lib/redis.ts` | זיכרון, dedupe, השהיות, אינדקס שיחות (Upstash) | לא |
| `lib/whatsapp.ts` | אימות חתימה, פענוח webhook, שליחה | לא |
| `lib/alerts.ts` | התראות לבעלת הקליניקה | פרטי קשר בלבד |
| `lib/transcribe.ts` | תמלול הודעות קוליות (אופציונלי) | לא |
| `app/api/meta/webhook` | הכניסה מ-Meta | לא |
| `app/admin` | לוח בקרה: שיחות, השהיה, צפייה | לא |
| `app/demo` | סימולציית וואטסאפ בדפדפן, אותה ליבה | לא |

עיקרון: הליבה לא יודעת מאיזה ערוץ הגיעה ההודעה. כדי להוסיף אינסטגרם או מסנג'ר כותבים מתאם חדש בלבד.

## 4. הסמנים

הסוכן מוסיף בשורה נפרדת: `[[END]]` סוף שיחה (נשלח כרטיס סיום פעם אחת), `[[HUMAN]]` ביקשו אדם, `[[ALERT]]` מצוקה. המערכת מסירה אותם לפני השליחה, משהה את הבוט בשיחה (24 שעות) ומתריעה. הסמנים לעולם לא מגיעים לפונה.

## 5. שכפול לקליניקה אחרת (רשימת בדיקה)

1. שכפול הריפו.
2. להחליף את `lib/prompt.ts`: שם הקליניקה, מה היא עושה, קהל, גבולות, נוהל בטיחות. השארו את מנגנון הסמנים.
3. להחליף את `lib/knowledge.ts`: שיטה, שאלות נפוצות, התנגדויות, "מה לא אומרים".
4. להחליף בשני הקבצים את קישור היומן, האתר ומספר הוואטסאפ (כרטיס הסיום ו-`FALLBACK_MESSAGE` ב-`lib/prompt.ts`).
5. ליצור אפליקציית Meta + מספר וואטסאפ נפרד לקליניקה החדשה.
6. פרויקט Vercel חדש, Upstash חדש, ומשתני סביבה חדשים (ראו `.env.example`).
7. לעבור על `/demo` עם חמשת התרחישים ולאשר סגנון לפני שמחברים מספר אמיתי.

## 6. מה בנוי ומה עדיין לא

בנוי ונבדק (13 בדיקות אוטומטיות, בנייה עוברת): הליבה, הסמנים, מניעת כפילויות, השהיה, כרטיס סיום חד-פעמי, הודעת גיבוי, webhook עם אימות חתימה, לוח בקרה, דמו, התראה במייל.

לא נבדק מול מערכות אמיתיות, כי זה דורש חשבונות שרק בעלת הקליניקה יכולה לחבר: שליחה ותקבלה בפועל דרך Meta, תשובות אמיתיות של Claude, Upstash, מייל דרך Resend.

עדיין לא נבנה:
- פולו-אפ אוטומטי אחרי 2, 24 ו-48 שעות. דורש תבניות מאושרות ב-Meta (הנוסחים כבר בספריית התוכן) ותזמון יומי.
- אישור ותזכורת לפגישה. דורש חיבור Webhook מ-Calendly.
- אינסטגרם ומסנג'ר (שלב ב׳).
- זיהוי מאיזו מודעה הגיע הפונה (Meta מעבירה נתוני referral בפניות ממודעות).
- תבנית `lead_alert` ב-Meta להתראה יזומה לוואטסאפ. עד שתאושר, ההתראה במייל.

## 7. לא אומתו

תמחור הודעות של Meta (כולל שינוי מ-1.10.2026 ודרישת אמצעי תשלום עד 30.9.2026) ואפשרות Coexistence על מספר קיים: לא הצלחתי לקרוא את התיעוד של Meta מהסביבה שלי. יש לוודא ב-developers.facebook.com לפני רישום מספר.

## 8. אבטחה

- חתימת `X-Hub-Signature-256` נבדקת בכל הודעה נכנסת.
- `/admin` ו-`/demo` נעולים ב-`ADMIN_KEY`.
- מפתחות נשמרים רק כמשתני סביבה ב-Vercel, לא בקוד ולא בצ'אט.
- תוכן שיחות נשמר 7 ימים ב-Redis.
